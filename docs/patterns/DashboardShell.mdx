# Dashboard shell

A monitoring layout that stacks a header, an optional left filter rail, a row of headline KPIs, and a responsive grid of chart cards above the footer — the standard frame for an OCHA situational dashboard.

## When to use

- A reader needs to **scan many metrics at once** (funding, people in need, severity) rather than read a narrative.
- The data **updates on a cadence** and the same frame is re-rendered each cycle.
- You have **3–5 headline figures** that deserve a KPI row, plus 2–8 supporting charts.
- The reader may want to **slice the view** (by country, sector, date) — that justifies the left filter rail.
- **Use something else when** the story is a single linear argument with prose and figures in reading order — reach for the [Report page](?path=/docs/patterns-report-page--docs) instead.

## Responsive

The shell is driven by the breakpoint tokens in `tokens/brand.css`.

- **Below `--cd-bp--md` (768px)** — single column. The filter rail collapses to the top (toggle it behind a button using `cd-filter`'s `data-cd-hidden` attribute), the KPI row stacks to one or two per line, and every chart card is full width.
- **`--cd-bp--md` to `--cd-bp--lg` (768–1024px)** — KPI row sits 2-up; `cd-grid--2-col` gives a 2-up chart grid. Keep the filter rail above the content rather than beside it.
- **`--cd-bp--lg` and up (1024px+)** — the optional filter rail moves to a fixed-width left column beside the content; KPIs run 3–4 across; `cd-grid` returns to its default 4-up (or `cd-grid--3-col`) chart grid.
- **Cap the whole shell at `--cd-max-width` (1220px)** so charts never stretch past a readable measure on `--cd-bp--xl` (1200px) and wider screens.
